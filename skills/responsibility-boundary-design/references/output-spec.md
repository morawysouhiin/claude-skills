# 成果物の仕様

## ファイル構成

| ファイル | 用途 |
|---|---|
| `responsibility-boundary.puml` | 全体図のソース |
| `responsibility-boundary.svg` | 上記をレンダリングしたもの(HTMLに埋め込む) |
| `failure-cases.csv` | 表A: 想定障害事例一覧(Excelで開く前提) |
| `boundary-definitions.csv` | 表B: 定義すべき責任境界一覧(Excelで開く前提) |
| `responsibility-boundary.html` | 閲覧用。図+表A+表B+前提と未確認事項 |

CSVは **UTF-8 BOM付き** (`encoding='utf-8-sig'`) で書く。BOMがないと Excel で文字化けする。改行を含むセルは引用符で囲む。

## 表A: 想定障害事例一覧(failure-cases.csv)

| 列名 | 内容 |
|---|---|
| `事例ID` | `H1-M01` 形式 |
| `引き渡し点` | `H1` |
| `引き渡し点の内容` | `Aシステム → SFTPサーバ(PUT)` |
| `障害モード` | `M01 未達` |
| `想定事象` | 具体名で記述。抽象的な記述は不可 |
| `業務影響` | 最終的に誰の何が困るか |
| `揉める点` | 当事者間で争点になること |
| `該当` | `該当` / `該当なし` |
| `該当なしの理由` | 該当なしの場合のみ。設計で防いでいるのか、単に想定外なのかを区別して書く |
| `関連する境界定義ID` | `D3, D7` のようにカンマ区切り |

**`該当なし` の行も必ず出力する。** 網羅の証跡そのものが設計レビューの成果物である。

## 表B: 定義すべき責任境界一覧(boundary-definitions.csv)

| 列名 | 内容 |
|---|---|
| `境界ID` | `D1` 形式 |
| `対象引き渡し点` | `H1, H2` |
| `観点` | `完了定義` / `検知` / `通知` / `ユーザ説明` / `復旧・費用` |
| `決めるべき事項` | 疑問文ではなく「〜を定める」の形で書く |
| `関連事例ID` | この事項が必要になる根拠。`H1-M01, H2-M08` |
| `案1` | 決め方の選択肢 |
| `案1_実装コスト` | 小 / 中 / 大 |
| `案1_残るリスク` | この案を選んでも残る問題 |
| `案2` | 同上 |
| `案2_実装コスト` | |
| `案2_残るリスク` | |
| `記載先候補` | 契約書 / 連携仕様書 / 運用手順書 / 監視設計書 |
| `現状` | `未定義` / `暫定合意あり` / `文書化済み` / `未確認` |

案は2つ以上。3つ目以降が必要なら `案3` 以降の列を足してよい。

`現状` の既定値は `未確認` である。ユーザが「決まっている」と言った場合のみ `文書化済み` にし、その文書名を `記載先候補` に書く。**確認していないものを `未定義` と断定しない。** 未定義と未確認は違う。

## HTMLの構成

この順序で出す。

```
1. 対象の関係性(当事者・連携方式・データフロー・業務上の意味)
2. 全体図(SVG埋め込み)
3. 引き渡し点の一覧(H1〜Hn とその内容)
4. 定義すべき責任境界(表B) ← 主成果物。図の直後に置く
5. 想定される障害事例(表A) ← 網羅の証跡。件数が多いので後ろ
6. 前提と未確認事項
```

表Bを表Aより前に置く理由: 読み手が最初に知りたいのは「何を決めればいいか」であり、その根拠(障害事例)は必要に応じて後ろを見ればよい。表Aを先頭に置くと、件数の多さで読み手が離脱する。

**表AはHTMLにも全件掲載する。** `該当なし` の行も省略しない。設計レビューの場では、その場で「このモードは検討したのか」を確認できることが重要であり、CSVを別途開かせるのは目的に反する。`該当なし` の行は視覚的に落として(`class="na"`)、読み飛ばせるようにする。

セクション6を省略しないこと。ヒアリングで埋まらなかった項目、こちらで仮定した項目を全て列挙する。**この成果物は相手方との協議に出る可能性がある。** 仮定と事実が混ざったまま渡すと、たたき台として使えなくなる。

## 書き方の制約(再掲。重要)

- 責任者を断定しない。「Bの責任」ではなく「Bが担うか、Aが担うか、共同で担うかを定める」
- 相手方を批判する記述を入れない。事象と論点だけを書く
- 人手の随時連絡のみに依存する案を単独で出さない。必ず機械的な検知手段を併記する
